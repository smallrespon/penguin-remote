# /sessions 收窄到「当前工作区」+ 序号改为粗体

`/sessions`（与 `/use`）的实时列表从「当前 (project, agent) 下全部未归档会话」收窄为「**当前工作区**下的未归档会话」；同时行序号从 markdown 有序列表语法改为粗体序号。动因是用户原话：「我要改的是输入 /sessions 显示当前工作区未归档的对话」「而且要实时获取」「序号你也命名错了，序号只显示了个位数，不能显示两位数以上的」——v1.5（ADR-0011）落地的是全量列表，把其他工作区的会话也混了进来。

**Status**: accepted (2026-10-22)

**背景（服务端能力事实，均已实测）**：

- `GET /api/projects/:p/agents/:a/sessions` 返回的每条会话都带 `workspace` 字段（服务端内部字段 `workspaceDir`），所以「按工作区过滤」不需要服务端任何改动，与已归档过滤一样在客户端做（ADR-0008）。
- 建会话时**不传** workspace，服务端会每次现配一个临时工作区（`agents/<agent>/workspaces/tmp-xxxxxxxx`，见服务端 `createTempWorkspace`）。因此「没设 `/workspace` 的聊天」的会话散落在一次性临时工作区里，按工作区过滤只会得到空列表——这种聊天必须继续看到全部未归档会话。Bridge 侧 `/status` 对这种聊天显示「临时工作区」（ADR-0005），两边口径一致。
- 飞书 post 消息的 `md` 标签按 CommonMark 渲染：行首 `N. ` 是有序列表标记，序号交给渲染器重排，`→ 1. …` 这种前缀行还会把列表打断成两段；两位数以上的序号在这种渲染下不可靠。粗体序号 `**N.**` 不是列表标记，任何渲染器下都原样显示。

**决策**：

- `SessionClient.listSessions(projectId, agentId, { workspace })` 新增可选工作区过滤：传了才过滤（`archived !== true` 之外再加 `workspace` 相等），不传或传 null = 不限工作区，与旧行为逐字等价。条目新增 `workspace` 字段。
- 工作区路径比较前归一（`normalizeWorkspacePath`：去尾斜杠，整串斜杠兜底回根目录）：用户手敲 `/workspace /root/x/` 与服务端返回的 `/root/x` 必须能对上，否则过滤永远不命中、列表凭空变空。服务端没报 `workspace` 的会话无法归属，限定工作区时一并排除。
- 网关 `sessionListFor` 传 `binding.workspace`（绑定里的空串 / 纯空白按「没设」算）；回复头部限定工作区时写清是哪个（`**未归档会话**（工作区 \`/root/x\`，共 N 个）`），没设时如实注明「未限定工作区」。空列表文案同样带工作区名。
- 当前会话不在（收窄后的）全量列表里时（典型：设了 `/workspace` 但正续接着别的工作区的会话，或它已被归档）注明去向，不让它凭空消失；空列表时同样注明，并且不再写「发一条消息就开始新的对话」——还绑着会话时下一条消息是续接（runner 对非空 sessionId 直接续接），那句会说谎。注明只陈述「不在这个工作区的未归档列表里」，不猜原因；在列表里只是排名超过展示条数时不必注明，头部已说明截断。
- 行序号改粗体 `**N.**`：不再依赖 markdown 有序列表渲染，两位数以上原样显示，且与 `/use <序号>` 严格一致。`/use` 仍打同一份（收窄后的）列表。
- 本地历史兜底路径（Registry `sessionsFor`）不按工作区过滤：它本来就只有本聊天的历史、且头部已用「本地历史会话」+ 失败注明区分来源（ADR-0008/0011），不在降级路径里追加工作区语义。

**Consequences**: 设了 `/workspace` 的聊天，`/sessions` 与 `/use` 都只看该工作区的未归档会话，其他工作区（含 Web/CLI/其他聊天建的）不再混入；没设工作区的聊天行为与 v1.5 一致（全量 + 注明）。切换 `/workspace` 后列表立即跟着变（实时查询，无缓存）。序号不再受飞书有序列表渲染影响，10 条以上与 `/use` 序号一一对应。

**Considered Options**:
- 没设 `/workspace` 时也强制按工作区过滤（取当前会话的 workspace）：服务端每次新建会话都换临时工作区，这种聊天的历史会话各属不同临时工作区，过滤结果基本为空。放弃。
- 让 Bridge 在没设 `/workspace` 时统一下发一个固定工作区（如 project 的 main_workspace）：会把群聊会话与 Web 端会话混进同一工作区，且改变了 Agent 的 cwd 语义，超出本次诉求。放弃。
- 序号补零对齐（`01.`–`50.`）：飞书 md 不是等宽场景，对齐收益有限，且与 `/use 1` 的输入形态不一致。放弃，保持 `**N.**`。
