# 步骤分组折叠：思考与工具调用收进同一个折叠面板

Run 回复卡片里，连续的思考分区与工具调用分区合并成**一个**默认收起的 `collapsible_panel`（分组面板），标题形如「🧰 运行完毕 · 2 步 · 41.4s」；组内每一步各是一个嵌套折叠面板（🔧 工具 / 🧠 思考），点开分组再点开某一步才看到参数、输出或思考全文。动因是用户原话：「思考和工具调用等等能被折叠在一起形如图片所示，运行完毕那两步可以被折叠」——截图里 PenguinHarness app 的形态是：一段连续执行收进一个「运行完毕 N 步 X.Xs」的分组，组内每步一行、各自可展开。ADR-0007 把思考与工具各自成面板，本 ADR 在其之上加一层分组。

**Status**: accepted (2026-10-22)

**背景（飞书能力事实，均已实测）**：`collapsible_panel` 是 Card 2.0 唯一的折叠载体，官方文档注明「容器最多嵌套 5 层、内部不支持 form」——分组面板内放每步的小面板是合法嵌套（本 ADR 实施前已用探针卡 om_x100b62aaa20c48a8ceffacfd65b4520 在测试群验证 API 接收）。面板内部元素计入单卡 200 元素上限（ADR-0006）；卡片 patch 无编辑次数上限、单次内容上限 30KB，Bridge 自设约 20KB 预算（ADR-0006）。`tool_call` / `tool_result` 事件原先不带时间戳（OmniMessage 的 `timestamp` 一直在，只是没往 RunEvent 传），每步耗时从此可得。

**决策**：

- **分组**：连续的 thought / tool 分区合并为一个分组面板；text 与 notice 分区打断分组（正文永远在组外，提示行独立成行）。一个分区横跨多组的形态不存在——分组只在相邻的思考/工具之间发生。
- **分组标题**：流式「🧰 运行中… · N 步」；定稿且组内每步都已闭合（工具有 output、思考有 endedAt）时「🧰 运行完毕 · N 步 · X.Xs」；定稿但有步未闭合时只写「🧰 N 步」——拿不到终态不谎报「完毕」（ADR-0007 的诚实原则沿用）。耗时 = 组内最后一个事件时间 − 第一个事件时间（按事件时间戳真实计算，预览期同样真实，不需要「现在」）。
- **组内每步一个嵌套面板**：工具行标题「🔧 名称 · 运行完毕 · X.Xs · `参数`」/「🔧 名称 · 运行中… · `参数`」（状态与耗时的口径与 ADR-0007 一致：只看 output 到没到；耗时 = tool_result 时间 − tool_call 时间），面板内容是参数围栏块 + 输出围栏块（沿用 ADR-0007 的 toolPanel 内容）；思考行标题沿用 ADR-0007 的 `thoughtPanelTitle`（「🧠 思考 · 运行完毕 · N 字 · X.Xs」），面板内容是脱敏后 2000 字上限的思考全文。
- **默认收起**：分组与组内每步都 `expanded: false`，与 ADR-0007 一致；预览期同样收起。
- **预算**：超预算时**整组丢弃**（靠中间的优先），丢弃处标注「……（中间省略 N 个分区）……」，N 按组内真实分区数计（一个组可能含多个分区，标注不谎报）。分组是「想看时再看」的细节，与 ADR-0007「思考优先丢」同一精神：答案正文与工具轨迹之间先保正文——这是用户在 grill 中明确的取舍（「直接丢中间整组」，不做组内先丢思考的两级预算）。
- **文本兜底路径不变**：思考仍是一行标签、工具仍是名称+参数+输出围栏，没有分组、没有状态词、没有耗时——文本消息没有折叠载体（ADR-0007 边界沿用）。
- **事件时间戳**：`tool_call.done` / `tool_result.done` 的 RunEvent 增加 `at` 字段（omni.ts 从 OmniMessage 的 timestamp 带出，缺省兜底当前时间）；`ToolPart` 相应记 `startedAt` / `endedAt`。只驻内存，不落 `runs.jsonl`、不进日志。

**Consequences**: 长 Run 的卡片更贴近 app 的形态：收起态一个分组只占标题一行，点开可见每步、再点开可见详情；元素个数上升（一组 K 步计 2K+1 个元素），200 元素上限更易触及，但预算装配会先整组丢弃，实测不会被元素计数卡死（超限即丢组，丢到达标为止）。用户手动展开的面板会被后续 patch 重置收回起态（ADR-0006 已记录的代价）。每步耗时依赖服务端事件时间戳，缺时间戳的事件按「缺时间排最后/不显示耗时」处理，不编造。

**Considered Options**:
- 组内超预算时先丢思考子面板、再丢整组：能多保工具轨迹，但要引入两级预算装配（组内一套、组间一套），复杂度和测试面都上一倍；用户明确选了「直接丢中间整组」。放弃。
- 分组标题不带图标前缀（完全照截图的「运行完毕 2 步 41.4s」）：与现有「🧠 思考 · …」「🔧 名称 · …」的图标体系不一致，扫读时分组与步骤容易混；用户在 grill 中选了带 🧰 前缀的版本。放弃。
- 组内每步渲染成普通 markdown 行（不嵌套面板）：详情没处放，要么全堆在组里（展开即刷屏），要么丢弃；嵌套面板让「展开一组 → 只看想看的那步」成立。放弃。
