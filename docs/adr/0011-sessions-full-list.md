# /sessions 全量未归档列表（50 条截断 + 总数注明）

`/sessions` 的实时列表从「前 10 条」扩到「全部未归档会话，截断到 50 条并注明总数」。动因是用户原话：「我要支持的 /sessions 能展示当前工作区未归档的所有对话，然后 use 支持跳换到那次对话」——ADR-0008 落地时客户端截断到 10 条，未归档会话多的项目下早期会话看不见也跳不了。

**Status**: accepted (2026-10-22)

**背景（服务端能力事实，均已实测）**：`GET /api/projects/:p/agents/:a/sessions` 不带分页参数时返回该 Agent 的**全量**会话（pre-paging 契约，见服务端 `agentSessionsRoutes`：paging 缺省即全量），未归档过滤 / 排序 / 截断一向都在 Bridge 客户端做（ADR-0008）。也就是说「列全量」不需要服务端任何改动，只是把客户端的 `slice(0, 10)` 放大并按展示层截断。

**决策**：

- `listSessions` 去掉条数截断，返回当前 (project, agent) 下**全部**未归档会话（仍按 `lastActiveAt` 倒序，缺时间排最后）；本地 Registry 兜底路径保持原有口径（`sessionsFor` 的 `HISTORY_LIMIT=10`），它只是降级路径，不假装全量。
- 展示层截断到 **50 条**：回复头部注明「共 N 个未归档会话」，超过 50 条时注明「显示最近 50 个」。`/use <n>` 在这份（截断后的）列表上按序号跳转——未列出的更早会话不可跳，文案如实说明，不虚构序号。
- 序号、`→` 当前会话标识、`/use <序号>` 提示等行格式不变（ADR-0008）。
- 查询失败退回本地历史的注明文案不变（ADR-0008）。

**Consequences**: 未归档会话 ≤50 的项目完全「所见即可跳」；超过 50 个时头部总数给用户预期，更早的会话需要先在别处（Web/CLI）归档或活跃化才能进前 50。飞书单条文本消息的长度远大于 50 行列表（每行约 80–120 字符），不触及平台上限。`/use` 的序号语义不变，仍以「最近一次 `/sessions` 拉到的同一份列表」为准——实时列表在两次命令之间可能变化，这与 ADR-0008 的既有语义一致，不引入缓存。

**Considered Options**:
- 不设上限全列：会话数上百时消息会很长，且飞书侧阅读体验差；用户选了 50 条截断 + 总数注明。放弃。
- 分页（`/sessions <页码>`，每页 20 条）：多一步翻页操作，且 `/use` 序号要区分页内/全局，复杂度上升；用户未选。放弃。
- 保持 10 条不动：与用户明确诉求「所有对话」相悖。放弃。
