# 思考进折叠面板 + 折叠块状态标识

Run 回复卡片里，思考分区从一行标签改为默认收起的 `collapsible_panel`，面板内放完整思考全文（先脱敏再截断，每个面板上限 2000 字）；工具面板标题补上状态标识「运行中… / 运行完毕」。动因是用户对照 PenguinHarness app 的原话：「你的回复中有部分思考和工具可以折叠，标识好像是运行完毕，主要在正文之间」——app 的 ThinkingBlock / ToolCallCard 都是默认收起的折叠块，标题带运行状态，思考点开有全文。这逆转了 ADR-0006「思考不存全文、不进面板」的决定：那一条的理由「避免刷屏」由折叠机制本身满足（收起态只占标题一行），而用户明确要「可以折叠、点开能看」。

**Status**: accepted (2026-10-22)

**背景（飞书能力事实，均已实测）**：`collapsible_panel` 是 Card 2.0 唯一的折叠载体，默认收起、点击展开，面板内部元素计入单卡 200 元素上限（ADR-0006）；卡片 patch 没有编辑次数上限，但单次内容上限 30KB，Bridge 自设约 20KB 预算（ADR-0006）。

**决策**：

- 思考分区 = 一个默认收起的 `collapsible_panel`：标题「🧠 思考 · 运行中… · N 字」（流式）/「🧠 思考 · 运行完毕 · N 字 · X.Xs」（定稿，耗时按事件时间戳真实计算）；面板内是完整思考全文，先 `redact()` 脱敏再按 2000 字上限头尾对半砍、中间标注省略字数，围栏代码块保真（思考文本可能含 markdown 记号与 ```，直接渲染会撑破卡片）。2000 字按脱敏后的全文计，省略标注计入这 2000 字，围栏另加约 8 字符；思考文本为空时面板给「（无思考内容）」占位（与工具面板的「（无详情）」同一套路）。
- 每段思考一个面板：一轮思考一个分区一个面板，与 parts 流、与 app 的 ThinkingBlock 一一对应。
- 工具面板标题补状态：`🔧 名称 · 运行完毕 · 截断参数`（收到 output）/ `🔧 名称 · 运行中… · 截断参数`（未收到 output）。状态紧跟工具名，与思考标题「名称 · 状态 · 详情」语序一致；app 的 ToolCallCard 把状态放在标题行右侧，飞书标题是线性文本，紧跟名称更易扫读。
- 预览与定稿的折叠面板都默认收起（`expanded: false`）；预览期思考面板同样放累积全文（同一 2000 字上限），随节流 patch 增长。
- 预算：思考面板优先丢。超预算时先把思考面板当丢弃首选（靠中间的优先），保住工具轨迹与正文答案；思考丢光仍超预算，再按现有规则从中间丢其他分区。preferred 优先于位置是刻意取舍：首尾的思考面板也可能先于中间的正文被丢，保底是头尾两个分区永远保留（最后一个分区永远是最终答案）。文本兜底路径的预算口径不变（render.ts 的 fitMiddleDropping 原样保留）。
- 定稿时仍未闭合的思考段（始终没等到 `thinking.done`）标题不带状态词，沿用 ADR-0006 的样式（拿不到终态，不谎报「完毕」）。
- 思考全文只驻内存（`PreviewState`），`runs.jsonl` 仍只记 RunReport（chat/session/状态/用量/耗时），不落分区内容；日志不打印思考。
- 文本兜底路径不变：思考仍是一行标签，且标签保持 ADR-0006 的旧样式（流式「🧠 思考中…（N 字）」、定稿「🧠 思考 · N 字 · X.Xs」）——「运行完毕」等状态词只出现在卡片路径，两条路径的标签函数因此分流（`thoughtPanelTitle` 服务卡片，文本路径用自己的私有函数）。

**Consequences**: 长 Run 的消息体量仍受折叠控制（收起态每段思考只占标题一行），用户点开可见思考全文；Bridge 开始驻留思考全文（仅内存），卡片预算多了一类大块内容，靠 2000 字上限与「优先丢思考」兜底；200 元素上限下每个折叠面板（含内部一个 markdown）计 2 个元素。用户手动展开的面板会被后续 patch 重置收回起态（ADR-0006 已记录的代价，思考面板同样适用）。脱敏时机从「累积时」变为「渲染时」：工具参数在 `tool_call.done` 一次性拿到完整字符串，可以累积时脱敏；思考只有渲染时才能拿到全文，跨 delta 的密钥只有在完整文本上才能被正则命中。

**Considered Options**:
- 思考只加状态标识、仍不折叠不放全文：与 app 形态不符（app 的思考块点开有全文），用户明确要「可以折叠」。放弃。
- 思考面板不设 2000 字上限、只靠整体预算：单个思考段可能上万字，会整体挤爆预算把答案挤丢。放弃。
- 超预算时所有分区同权：思考是「想看时再看」的内容，与正文答案争预算不合理；优先丢思考能在最紧张的预算下保住答案。放弃同权方案。
- 状态标识追加在工具标题末尾（贴近 app 的右侧排法）：参数最长 80 字，状态会被挤到很右边，扫读困难；且与思考标题「名称 · 状态 · 详情」语序不一致。放弃。
